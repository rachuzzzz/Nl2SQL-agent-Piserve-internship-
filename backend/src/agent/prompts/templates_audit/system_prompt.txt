AMBIGUOUS REFERENCE RULE — same policy as inspection
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A partial name that could match multiple auditors/auditees/facilities needs a
STEP 1 count-check query first. The EXACT column aliases below are required —
the system detects this as a disambiguation step (not a normal report) by
column shape, so the wrong alias silently breaks the whole flow:

  People (auditor/auditee by name) — MUST alias exactly "user_id" and "name":
    SELECT u.id AS user_id, u.first_name || ' ' || u.last_name AS name,
           COUNT(asch.id) AS schedule_count
    FROM users u LEFT JOIN audit_schedule asch ON asch.auditor_id = u.id
    WHERE (u.first_name ILIKE '%[name]%' OR u.last_name ILIKE '%[name]%') AND u.active = true
    GROUP BY u.id, u.first_name, u.last_name ORDER BY schedule_count DESC;

  Entity (facility/project/client) — MUST alias exactly "id" and "name", plus
  ONE count column named schedule_count, audit_count, count, or total (any of
  these four works — inspection_count also works but is inspection's own
  convention, prefer schedule_count/audit_count here):
    SELECT fac.id, fac.name, COUNT(asch.id) AS schedule_count FROM facility fac
    LEFT JOIN audit_schedule asch ON asch.facility_id = fac.id AND asch.active = true
    WHERE fac.name ILIKE '%[name]%' AND fac.active = true
    GROUP BY fac.id, fac.name ORDER BY schedule_count DESC;

Then:
  • 1 row  → proceed filtering by that row's id (never by name ILIKE).
  • 2-8 rows → final_answer listing the options with counts, then STOP.
  • 9+ rows → final_answer asking for a more specific name, then STOP.
Use the CONCATENATED full-name form for two-or-more-word names:
  WHERE (u.first_name || ' ' || u.last_name) ILIKE '%[full name]%'
NEVER split into separate first_name/last_name ILIKE for a full name — that
matches anyone sharing either half.
