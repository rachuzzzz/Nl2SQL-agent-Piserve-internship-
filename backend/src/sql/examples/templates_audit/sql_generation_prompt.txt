### DEFAULT SCOPE FOR CORRECTIVE ACTION LISTINGS:
  A general "list/show corrective actions" question (no explicit status/approval ask) must
  exclude rows still pending adequacy approval by default — add
  AND aca.adequacy_status = 'APPROVE' (equivalently: AND aca.corrective_action_id != 'CA_DRAFT').
  ONLY omit this filter when the question explicitly asks for pending/draft/unapproved
  corrective actions, or specifically about adequacy review/approval status — in that case
  showing 'CA_DRAFT' rows is correct and expected.

  DOES NOT APPLY TO EXISTENCE CHECKS — CRITICAL DISTINCTION, confirmed live as a real bug:
  A 'CA_DRAFT' row is a REAL corrective action that WAS raised, just not yet adequacy-approved.
  For "audits/reports with NO corrective actions", "has a CA been raised against X", or any
  other existence check, adequacy_status is irrelevant — check row existence instead:
    AND aca.id IS NULL   (after a LEFT JOIN audit_corrective_action aca ON aca.audit_id = arep.id)
  NEVER write (aca.corrective_action_id IS NULL OR aca.corrective_action_id = 'CA_DRAFT') for
  an existence check — that wrongly treats "raised but not yet approved" as "never raised",
  silently inflating the "no corrective actions" count with audits that DO have one raised.

### OBSERVATION → CORRECTIVE ACTION LINK:
  audit_corrective_action.observation_id (UUID) → ai_audit_answers.submission_id (varchar)
  JOIN: aaa.submission_id = aca.observation_id::varchar  ← cast UUID to varchar, NOT the other way
  submission_id groups ALL answers for one observation (Risk Level, Requirement Type, free-text etc.)
  To get the free-text finding: MUST filter WHERE aq.label = 'Findings / Remarks'
  NOTE: unlike inspection (whose free-text field is literally labeled 'Observation'), audit's
  conduct-form question set has NO question labeled 'Observation' — confirmed live. The
  equivalent free-text field is labeled 'Findings / Remarks'.

  "observation text for this CA" / "what was the finding":
    JOIN ai_audit_answers aaa ON aaa.submission_id = aca.observation_id::varchar
    JOIN ai_questions aq ON aaa.element_id = aq.element_id
    WHERE aq.label = 'Findings / Remarks'   ← ALWAYS add this to get free-text, not Risk Level/Type

  "corrective actions for this audit report" / "all CAs for this audit":
    WHERE aca.audit_id = arep.id  ← all CAs for the whole report (aca.audit_id is UUID FK to arep.id)

  NEVER confuse: one observation ≠ all observations in an audit report.

### AI FLAT TABLES — form question/answer data for audit:

    FROM ai_audit_answers aaa
    JOIN ai_questions aq ON aaa.element_id = aq.element_id

    ORDER BY aaa.submission_id, aaa.created_on
